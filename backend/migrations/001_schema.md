# Schema v1
SQLAlchemy metadata creates users, audits, workloads, candidates, experiments and telemetry on first startup. Workload/candidate natural names are UNIQUE; experiment snapshots are immutable JSON. Foreign keys prevent orphan references. Index trials affect only the dedicated telemetry table, under MySQL GET_LOCK, and drop the trial index after each execution. No production database connection is accepted.

# Credential rotation (no relational schema change)
Rotation state lives in Redis, not MySQL: `credential:state` is a hash of active/previous generation URLs (connection strings incl. passwords), generation numbers, version and timestamps; `credential:runs:<generation>` is a set of in-flight experiment IDs pinned to that account generation; `credential:conns:<instance>` is a TTL (90s) hash of per-generation checked-out connection counts per process. On first start with no state key, the DATABASE_URL env var seeds generation 1. Restarts recover the effective account from Redis; terminal experiments are reconciled out of the run sets and stale-generation engines are disposed. API responses and audit records always redact the password as `***`; only Redis and the process environment hold full connection strings, so Redis must be access-controlled.
